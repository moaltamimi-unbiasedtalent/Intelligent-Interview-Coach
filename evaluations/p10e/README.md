# P10E evidence layout

- `authorization.json`: the owner authorization record (2026-10-19): USD 10 and 300 provider calls CUMULATIVE, 20,000 input and 4,096 output tokens per request (raised from 2,000 in authorization v3, P10E-R1; history preserved in the file), 60 s, 1 retry, concurrency 2, all approved by the Product Owner. USD 15 is a potential ceiling and is NOT approved. `paid_execution_enabled` must be the boolean true; it is enforced by the runtime guard together with the owner checks. The designated execution environment and the ledger genesis id are recorded here; a second ledger cannot be created or accepted.
- `pricing_snapshot.json`: published provider prices for the registry code defaults and for the models the designated environment actually resolves (provider metadata at one moment, not a bill).
- `execution_plan.json`: the offline plan (assumptions stated).
- `live/<run_id>/`: one directory per real provider run (`meta.json`, `calls.jsonl`, `summary.json`, optional `review_packet.json` and `rescore.json`), created exclusively and never overwritten. `live/provider_snapshots/`: read-only provider usage snapshots and the reconciliation. Per-run evidence only: the AUTHORITATIVE cumulative ledger lives OUTSIDE the repository (`$HOME/.ask4mo/p10e-ledger`, `P10E_LEDGER_DIR`) and is never committed.
Offline evidence (P10C-G, P10D, P10D-R1) lives elsewhere and is not touched. Paid execution is manual only (`P10E_LIVE=1`), never in CI.
- `r1/` (P10E-R1): pre-registered `interview_cases.json` and `multilingual_cases.json` (versioned, SHA-256 recorded in `registration.lock.json`, committed before any live call). Human metrics stay `PENDING_HUMAN_REVIEW`; no thresholds exist. See `docs/capstone/p10/P10E_R1_CORE_LIVE_QUALIFICATION.md`.
- `policy/` (P10E-R2): the prospective, hash-locked candidate-policy contract (`candidate_policy_contract_v1.json`, `registration.lock.json`). Separate from `r1/`; the R1 registered records are never touched. See `docs/capstone/p10/P10E_R2_CANDIDATE_GROUNDING_POLICIES.md`.
