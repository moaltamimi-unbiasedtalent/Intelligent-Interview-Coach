## 4. Entitlement architecture

`src/application/model_profile_access.py` is the ONE policy; `src/application/plan_state.py` is the single definition of "active Premium subscription" shared with the P2-B history policy (a read of the existing `EntitlementService`: `source == "subscription"` and the Premium plan family). There is no new subscription system, writer or key. Rules: Basic fast only; Premium all three; Premium defaults to Balanced (the existing default), Basic to Fast; `premium_preview`, client plan labels or headers, unsigned claims, expired or unreadable state, unknown plan codes and unverified state are never Premium (`unresolved` and every unknown resolve to Basic, fail closed). Accepted values are exactly `fast`, `balanced`, `advanced`; a provider model id, an alias, another case, padding, a non-string or "medium" is rejected (schema Literal for requests, `ModelProfileInvalid` for the policy). The slug always comes from the server registry through the profile id; unknown extra request fields are ignored.
Enforcement points (all BEFORE any provider invocation): Practice create (`POST /interviews`, new optional `model_profile`), Mo run (`POST /agent/run`), and Mo continue and resume (the stored run profile is re-checked against the caller's CURRENT entitlement, so a downgraded account cannot keep spending Balanced or Advanced on an old run; no extra read while the gate is off). Refusals: 403 `model_profile_not_authorized`; 422 `model_profile_not_available` (Practice selector inactive) and `invalid_model_profile`; fixed copy with no profile echo, plan, price or upgrade wording.
