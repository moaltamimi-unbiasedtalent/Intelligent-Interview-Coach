# Pilot 2 participant tasks (RC-P10-003)

Read aloud or hand over one task at a time. Do not explain the product first. Use synthetic assets only. T8 runs only where the environment supports voice; unsupported external realtime capability is never a participant failure.

| ID | Task | What to observe |
|---|---|---|
| T1 Orient | On the public Home page: what is Ask4Mo, who is it for, what would you do first? | comprehension, hierarchy, imagery, first action |
| T2 Get started | Sign in, go through onboarding / landing, find Help or the tutorial | discoverability of Help/tour, language selection |
| T3a Opportunity | Create an Opportunity for a role (one job in one place) | empty-state clarity before creation, discoverability, "one job in one place" |
| T3 Prepare | Using the synthetic job description, begin preparing; use Brief/Detailed; find Sources; choose a next step | Mo response structure (where available), Sources, next step |
| T4 Documents / evidence | Add the synthetic CV; review it; accept one item, correct one, reject one; open the Story Bank | provenance/status comprehension |
| T5 Interview Practice | Start practice; answer; read feedback; interpret the score; choose the next action | question→answer→feedback→next, score comprehension |
| T6 Return journey | Open History and Progress; open a previous report; resume where applicable | return-path clarity, empty states for a new account |
| T7 Privacy / trust | Say what is private; check what a workspace member can see; share and revoke; find export/delete; open the Data & Privacy Center and the Trust page | private-by-default understanding, no automatic member visibility, sharing/revocation, trust |
| T8 Voice (only if supported) | Listen to a question; speak an answer; edit the transcript; explicitly submit | transcript editing, explicit submit |
| T9 Final exploration | "If you came back tomorrow to prepare for another interview, what would you do?" | perceived usefulness |
| Debrief | After use only: which parts felt AI-generated vs from external sources vs verified; what Memory saved and when; who can see your data; was any score or feedback unclear | provenance, Memory, visibility, score clarity |

Include a support or error/recovery moment only when it arises naturally (candidate-facing support/ticket discoverability, truthful error and recovery); do not stage Admin tasks. If a model answer is unavailable because providers are off, record INFRASTRUCTURE / PROVIDER LIMITATION and continue.
