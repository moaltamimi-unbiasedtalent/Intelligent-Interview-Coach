## Detail and recommended direction
**P2-01 (REMEDIATED - PENDING HUMAN REVALIDATION).** This is a discoverability and comprehension failure, **not** evidence of a data leak. The backend (sharing, listing, revocation, isolation) was already correct and was not changed. Remediation (frontend only, branch `feat/pilot2-p2-01-sharing-discoverability`): the Data & Privacy page now opens with a "Manage sharing & access" action beside a "nothing is shared automatically" note; the sharing overview card is an actionable link; the sharing section is a real `#sharing` landmark (the previous `#sharing` anchor had no target) with scroll margin, a view-only note, explicit "Revoke access" and a private-by-default empty state; Workspaces links its "Shared by you" section to `/account/data#sharing`. Automated unit, Playwright and backend regression tests prove the control is implemented and reachable, but the original issue was HUMAN discoverability, so it is **not closed** until targeted human revalidation. Original direction: make sharing state, sharing controls and revoke controls far easier to find in the candidate journey. Evidence ambiguity on the related private-by-default question is recorded in the results document (section 9).

**P2-02 (REMEDIATED - PENDING HUMAN REVALIDATION).** The pilot ran from an isolated candidate worktree without developer datasets, so this is not automatically a retrieval defect. Conclusion at the time: the source-backed experience was not validated. Remediation: an isolated, synthetic, offline knowledge fixture and builder/validator (`scripts/pilot/`, see `P2_02_ISOLATED_KNOWLEDGE_FIXTURE.md`) that uses the production Chroma, local embedder, hybrid retriever and retrieval-only boundary, with a fail-closed protected-path guard; deterministically validated (`tests/test_pilot_isolated_knowledge.py`). An isolated source-backed retrieval environment now exists; the candidate-facing source experience has not yet been re-tested by humans, so this is not closed. Original direction: Direction: a safe, isolated, representative knowledge fixture or a reproducible pilot knowledge environment; never copy or link the protected developer knowledge base.

**P2-03 (REMEDIATED - PENDING HUMAN REVALIDATION).** Root cause confirmed: the answer score rendered as a bare number (the word "score" existed only in an `aria-label`), and the seven rubric dimensions the backend already returns were not shown, so a candidate could not tell what the number meant, whether it covered this answer or the whole interview, or what to do next. Remediation (frontend only, branch `feat/pilot2-p2-03-score-clarity`; no backend scoring change because there is no calculation): a visible "Interview Answer Score" label with `74 / 100`, an explicit statement that it is practice feedback for this answer only and that the full interview has a separate Practice Readiness score (the final report label is unchanged), the seven EXISTING dimensions shown as `x / 10` with short descriptions (credibility explained as consistency and support in the submitted answer text only, never voice, never truth detection), a statement that the dimensions are not a formula for the 0 to 100 score, a next-step cue pointing to the existing feedback sections, and the same presentation in Deep Dive. No arithmetic or weighting is introduced, no score bands are invented, and no hiring-prediction wording is used. Covered by 10 new unit tests, new Playwright regression (including German and Russian) and the existing evaluation-contract tests; not closed until targeted human revalidation. Original direction: an explicit "Interview Answer Score" label, an explanation of what the number means, a clear per-question versus overall distinction, the existing structured dimensions where available, and a clear next action. No new deterministic scoring formula is introduced.

**P2-04.** Direction: a stronger provenance presentation with four states, AI generated, Source-backed, Candidate-provided and Candidate-verified, and no unsupported verification claim.

**P2-05.** Direction: say why each onboarding step matters, add visual explanation, and make Help and the tutorial easier to find.

**P2-06.** Existing W9.10 positioning rules stay binding: no unsupported competitor-superiority claim. Note: after the pilot candidate was frozen, PR #137 (merged to main as the v4 website work) added a plan comparison, a coaching-format comparison, a founder section and Getting Started content. **That is an unevaluated change on main, not part of RC-P10-003 and not validated by this pilot.** Whether it resolves the observation needs re-evaluation with participants.

**P2-07.** Not implemented here. Any future design must derive only from actual structured interview and evaluation history, must not invent candidate weaknesses, must not use a deterministic scoring formula, and does not commit to a provider or API yet.

**P2-08.** Direction: evaluate output-style changes under controlled regression coverage; do not rewrite prompting globally without an evaluation.

**P2-09.** Reproduce in Opera (version and permission state recorded) before calling it a product defect; Safari worked, and the Web Speech support in Opera may simply differ.
