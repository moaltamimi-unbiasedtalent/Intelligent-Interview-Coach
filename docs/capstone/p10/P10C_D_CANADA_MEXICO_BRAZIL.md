## 4. Taxonomy handling and edition safety
Identities are `(taxonomy namespace, edition, native code)` with a stable internal key: for `noc`, `sinco` and `cbo` the key includes the edition, so the same code in two editions is two nodes (tested). **The catalogue records no real edition and no code format for NOC, SINCO or CBO** (they stay `unknown` and `identified_externally`), because none has been acquired; nothing about their real structure is asserted. The corpus uses invented editions `fx-ed1` and `fx-ed2` with invented formats. An unknown edition matches no known edition; a production import refuses an unknown edition. Native codes are strings (a hyphenated Brazilian-style code is preserved). Occupation labels are never used to infer codes.

## 5. Country profiles and regions (`compensation/countries.py`)
A profile holds only non-data facts: ISO country, taxonomy scheme, national currency (ISO 4217: CAD, MXN, BRL) and the ISO 3166-2 subdivision vocabulary used to VALIDATE a region value (13 Canadian provinces and territories, 32 Mexican states including Mexico City, 27 Brazilian states and the Federal District). A region outside the vocabulary is rejected, never guessed; `ON` and `CA-ON` normalise to `CA-ON`; a name such as "Ontario" is not translated or matched. Profiles record no source, edition, code format, language or occupation.

## 6. Adapters (`compensation/country_adapters.py`; QUALIFIED OFFLINE)
`canada_records`, `mexico_records` and `brazil_records` transform parsed source rows into the SAME `CompensationRecordV2` (no country money model) and count rejections by reason. The caller supplies the source's own vocabulary as explicit maps (statistic, pay period, earnings concept, population, method); an unmapped label is rejected, never guessed; the currency must equal the national currency; a level is used only if the source publishes it or the caller supplies a code-length rule, otherwise it stays `unknown` and the importer rejects the row (no evidence class). Canada: national and provincial figures stay separate (a provincial row is never national and a national figure is never inferred from a province); an hourly figure stays hourly. Mexico and Brazil: the earnings concept and population are REQUIRED (Brazil also the method), so individual earnings, employment income, wage statistics, formal-sector compensation, administrative records and survey evidence are never one figure; **household income can be mapped but is then refused by the importer and by a database CHECK as not occupation compensation.** Money is exact (P10C-C); no arithmetic converts a period or currency (AST test).

## 7. Registry-gated importers (`compensation/country_import.py`) and crosswalk safety
`import_taxonomy_nodes` and `import_crosswalk` go through the P10C-A registry: production mode needs approval for ingestion, a verified licence, a genuine origin and a KNOWN edition; fixture mode needs a synthetic source and stores nothing that can be evidence. One transaction, idempotent, rejections as reason codes only. Crosswalk rows are accepted only as source-provided statements with known editions on both sides; an equivalence needs a VERIFIED statement; a RELATED row stays RELATED; a conflicting statement is rejected, never overwritten; an unknown code or edition is rejected. No crosswalk is manufactured: none exists for any country (readiness X1). Compensation rows use the P10C-C importer unchanged in its gates.

## 8. Schema change and the two disclosed behaviour changes to P10C-C
Migration `0038_compensation_concepts` adds `earnings_concept`, `population_scope` and `evidence_method` to `compensation_v2_records`, adds them to the natural key, and adds CHECKs including `earnings_concept <> 'household_income'`. It is necessary because figures that measure different things cannot otherwise be told apart or kept from combining. Existing rows (none exist in any environment) keep `unknown`; record keys of unknown-definition rows are unchanged. Batch mode keeps all CHECK constraints on SQLite (verified), PostgreSQL uses plain ALTER, and the **downgrade refuses before changing anything when records differ only by these columns**. Disclosed changes to the P10C-C layer: (1) the precedence policy is bumped to `p10c-d/1`: a regional figure from a national tier is classed by occupation specificity (C1 or C2) and labelled regional, returned only when that region is requested and never as national (PROPOSED, owner approval pending, D-14; it replaces the P10C-C rule that rejected regional rows); (2) a tie-break defect is fixed: records for several candidate occupations reached through relationships and carrying different values are now a CONFLICT instead of an arbitrary pick. Both are covered by updated and new tests; the P10C-C evaluator still passes.

## 9. C1 to C4, precedence and abstention (unchanged principles)
Classes still reflect actual source specificity (never the publisher's nationality): national detailed C1, national broad C2, international harmonised C3, C4 abstain. The versioned policy is reused with no country override. Eligibility (occupation, country, region, period, statistic, definition, source qualification) precedes precedence. Abstention or no-value outcomes are returned for ambiguity, a missing crosswalk, a non-operational source (default), missing evidence, unsupported geography, unknown basis or statistic, incompatible measures, an unverified edition and an incomplete citation; there is no cross-country fallback and no synthetic figure is ever presented.

## 10. Coverage matrix, geography and multilingual boundaries
The coverage levels for CA, MX and BR are **unchanged** (taxonomy source identified, compensation source identified or targeted, nothing qualified); only the limitation text records the new contracts and the fact that no node, crosswalk or record exists. Subnational granularity is represented by the region vocabulary and the `regional` geography level; a country source's precision is never assumed. Language availability comes only from source evidence: source languages for the three countries stay empty, no official alias is manufactured, and fixture labels in French, Portuguese, Spanish, German and English are fixture-declared test strings. The interface language, source language, alias language, employment country, taxonomy and compensation availability remain separate (the compensation request has no language or locale field; the occupation title language is only the language of the typed text). CAD, MXN, BRL, USD, GBP and EUR are never compared: FX and PPP remain NOT_CONFIGURED.
