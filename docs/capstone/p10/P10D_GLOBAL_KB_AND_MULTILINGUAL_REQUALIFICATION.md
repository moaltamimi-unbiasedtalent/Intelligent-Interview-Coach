## 3. Defects demonstrated by the corpus and fixed (bounded; candidate-visible changes documented)
Before the fixes 42 of the 154 cases failed on `origin/main`; after, 0 (both measured, same corpus).

| # | Defect | Fix | Candidate-visible change |
|---|---|---|---|
| D1 | A question naming any country outside DE/UK/US/EU (Canada, Mexico, Brazil, Chile...) detected nothing, so the country guard never fired and US wages or forecasts were returned for it | `copilot/knowledge/countries.py` (explicit names, 8 interface languages, ~35 countries); lower-case "us"/"eu" are no longer countries | such questions now abstain instead of showing another nation's statistics |
| D2 | Openings lane had no country filter (a German question received US openings) | same-country or labelled supra-national only | fewer, correct rows |
| D3 | EU aggregates were offered as "broader context" for any country, including non-European ones | EU family tags only for European countries (`tag_matches_country`) | |
| D4 | Vacancy lane mapped Germany to "germany" while the store keys "DE", never matched, then returned the first rows of EVERY country (Madeira, Cyprus, Latvia...) for a German question, and the 412-case evaluator counted 8 such cases as sufficient | exact national-row matching, abstain when absent | 8 `pc_current_demand_*` cases now return the real German row (count unchanged, now correct) |
| D5 | Injection scanner was English only (German, French, Spanish, Italian, Portuguese, Dutch, Russian, Arabic attacks were allowed) | accent-folded Unicode rules for the two highest-impact attack classes | non-English injections in a question or retrieved chunk are blocked or excluded |
| D6 | BM25 tokeniser `[a-z0-9]+` split words at accents and dropped Arabic and Cyrillic entirely | Unicode, accent-folded tokens (ASCII unchanged) | accent-free queries match; non-Latin lexical matching works |
| D7 | Zero or negative similarity chunks were padded in as evidence | floor at similarity > 0 | irrelevant padding removed where there is no overlap at all |
| D8 | Role search used SQLite ASCII `lower()` (a capitalised non-ASCII title never matched) | registered Unicode fold for search only | |
| D9 | The BM25 index over every stored chunk was rebuilt on EVERY request (about 0.65 s for 14,087 chunks versus about 50 to 90 ms of retrieval) | cached on the shared store keyed by size and mutation revision | first request unchanged, later ones about 1 ms |
| D10 | Country-bound narrative (labour-market notes, industry surveys) tagged to another nation was returned | filtered by country tag for those document types only; O*NET, ESCO and ISCO definitions are never filtered | |
| D11 | Synthetic-fixture-origin rows (CareerOneStop certifications and licences) were shown under the real publisher's name with its URL | labelled "[SYNTHETIC SAMPLE DATA, not official data]" and "(synthetic sample)"; still returned | label only; coverage unchanged |
| D12 | The research-cache isolation fixture was pytest-only, so a standalone evaluator read and wrote the developer cache | installed when `tests.conftest` is imported | none |

## 5. Multilingual evaluation (measured per language, no equality assumed)
Supported product languages: en, de, fr, es, it, pt, nl, ru (interface). Knowledge-base languages: the seven without Russian. **Arabic is not supported anywhere**; it is measured only. Results (full matrix in the generated file): country-name detection works for en, de, fr, es, it, pt, nl; **structured lanes and routing are English-keyword driven, so a non-English question reaches the structured stores only if the paid query-translation model rewrites it (not measured; L-ROUTE-1)**; occupation aliases resolve only for stored aliases (de "Krankenpfleger", fr "infirmier", de "Buchhalter" yes; "Pflegefachkraft" no, correctly: no equivalence invented); cross-language retrieval cannot work with a lexical embedder (L-XLANG-1); injection detection now covers all eight languages and Arabic; Russian and Arabic lexical document matching works after D6 but is not a product claim; Russian country names are matched as whole forms only (L-RU-INFLECT, fails safe). Language never selects a country ("Was verdient eine Pflegekraft?" detects none).

## 6. Geography, occupation, citation, grounding
Country-native, regional and harmonised-labelled evidence are distinct in the cases (US, UK, DE, EU; CA, MX, BR, CL, AR abstain with a coverage note). Occupation: exact title, supported alias, ambiguous (clarification, evidence withheld), unsupported (narrative withheld in `retrieve_evidence`), competing definitions (two sources both cited), unavailable context. The KB never overrides an abstention (the P10C resolver is not wired in at all). Citations: all 8 citation and grounding cases are SYNTHETIC CITATION TESTs with a scripted responder (correct source id, title with year and country, `.invalid` URL, invalid markers removed, none invented, unavailable evidence yields no citation). Grounding: coverage notes reach the prompt, trust-separated blocks, model failure falls back to evidence text only, poisoned chunks (English and German) are excluded before the prompt, benign text containing "ignore" is not excluded, secrets are redacted, system-prompt leakage is flagged.

## 7. Ingestion security and research cache
Malformed PDF, unsupported types, empty and binary files are controlled errors; injection text is kept verbatim at ingestion and excluded at retrieval; zero-width characters are cleaned. **Accepted operator-trust limitations** (not candidate-reachable): no per-file size limit in the legacy loaders (L-INGEST-SIZE; the governed Admin pipeline has limits) and a sidecar can override provenance metadata (L-META-1). Governed knowledge: an unapproved, revoked or retired version is never returned even when physically indexed. Tenant boundary: the retrieval signature carries no user or workspace and candidate documents are not in the path. Research cache: isolated for evaluators (D12), no import path into retrieval, TTL, malformed entries ignored, key built from safe parameters only. Developer caches were not modified or cleared (37 files unchanged).

## 9. Performance (measured; wall clock; machine dependent)
Developer-local (real 14,087-chunk store, copied to a temporary directory and queried; 412 questions): embedding lookup p50 0.04 ms, vector 3.2 ms (p95 3.6), keyword BM25 21.6 ms (p95 53.6), hybrid 24.5 ms (p95 57.2), `retrieve_evidence` end to end p50 54.4 ms (p95 89.4); one-off Chroma open 124 ms and BM25 index build 636 ms; index 114 MB on disk, 512 dims, `local/local-hash-v1`. Per-request service construction was about 650 ms before D9 and about 1 ms after the first request. Fixture (28 chunks, Chroma): hybrid p50 1.3 ms, context assembly 0.023 ms, citation resolution 0.010 ms, translation cache hit versus miss about 17x, non-English versus English hybrid p50 1.31 versus 1.34 ms (no overhead). The remaining bottleneck is the pure-Python BM25 scoring (about 22 ms p50 over 14k chunks); not optimised (no demonstrated user impact).
