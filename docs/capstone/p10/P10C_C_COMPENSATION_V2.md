## 3. V1 architecture and limitations (EXISTING IMPLEMENTATION, unchanged)
V1 (`src/copilot/knowledge/compensation.py`) is a flat SQLite table filtered by country, year, native code or title substring; the router's country priority is hard-coded for DE, US, UK and EU. Limitations: no pay basis (gross or net), no taxonomy namespace or edition, no source edition, publication date or reference period, bounds without declared semantics (the reader uses the published 10th and 90th percentiles), values stored as floating-point REAL, no evidence class, precedence, qualification or provenance fields, and the occupation level (OEWS `O_GROUP`) is not stored, so **C1 versus C2 cannot be derived from the V1 store and requires re-reading the source file**. V1 is untouched.

## 5. Money and measurement model
Domain amounts are `Decimal`; the database stores exact scaled integers (`value_units`, `lower_units`, `upper_units`, `amount_scale` 0 to 6), verified on SQLite and PostgreSQL (`bigint`). A float is rejected as input; more than six decimals is refused rather than rounded; zero and negative amounts are not valid. A missing value is a status (`suppressed`, `not_available`) with NULL amount, never zero (database CHECK). Original currency (ISO 4217), pay period (hourly, daily, weekly, monthly, annual), pay basis (gross, net, unknown), statistic (median, mean, percentile with a rank, unknown) and bounds semantics are stored as published; nothing is converted, annualised or rounded, and a test scans the package for period or currency arithmetic. Pay basis and statistic default to `unknown` and an unknown value is comparable with nothing; an unknown statistic is never presented.

## 6. CompensationRecordV2
Fields: canonical occupation (resolved from the NATIVE code in an explicit taxonomy edition, never a title), native code, taxonomy scheme and edition, occupation level (detailed, broad, unknown), country, region, geography level, currency, pay period, pay basis, statistic, percentile, value status, value, bounds and their semantics, source reference, source edition, publisher and dataset snapshot, reference year and period, publication date, data vintage, evidence class, precedence category, qualification status, limitations, provenance, import batch. Constraints (service and database): a reported value is positive; a percentile only for the percentile measure; bounds come as an ordered pair; every row names source, edition and native code; the natural key is unique; evidence class is C1 to C3 only.

## 7. Canonical occupation integration
The importer links a row to a graph node only by an exact native identifier in a registered taxonomy edition; no node means rejection (`occupation_not_in_graph`), never a title match. The resolver reuses the P10C-B resolver: AMBIGUOUS, INSUFFICIENT_CONTEXT, UNSUPPORTED and NOT_FOUND are passed through and never replaced by a salary. Evidence for an occupation is found for the node itself and VERIFIED equivalents; a VERIFIED `broader` relationship (one hop) is a clearly labelled lower-specificity fallback; RELATED, NARROWER, unverified and derived-rule relationships never carry evidence. In operational mode a relationship must also be official-source-provided. **Today no SOC or UK SOC taxonomy nodes exist in the graph (only ESCO and ISCO), and no ESCO-to-SOC or ESCO-to-UK-SOC crosswalk exists, so no real US or UK record is linkable.** That is a documented blocker, not a gap hidden by a guess.

## 8. Source registry integration and ingestion (IMPLEMENTED; no second licensing system)
`production` mode needs `can_ingest` (approved for ingestion, VERIFIED licence, non-fixture origin), a known dataset edition (not `unknown` or `current release`), publisher and dataset attribution, a precedence category, and a known taxonomy edition per row. `fixture` mode needs a registered synthetic-fixture source and stores rows that can never be evidence. Rows are rejected with reason codes only (schema, currency, unit, source mismatch, unknown or unregistered taxonomy edition, occupation not in graph, region or level incoherence, undeterminable evidence class, conflicting value); nothing is repaired or overwritten. One transaction, idempotent (an identical re-import is a no-op), concurrency-safe, with an audit batch that stores counts and reason codes (no source content). Qualification of a measurement needs a named reviewer and a source of genuine origin and is audited.

## 9. C1 to C4 and source precedence
RECOVERED: C1 national detailed, C2 national broad, C3 international harmonised, C4 insufficient evidence (abstain), and the six-level order (national official occupation statistics, national public employment service, Eurostat harmonised, Cedefop intelligence, authorised secondary, insufficient evidence). PROPOSED: classification by ACTUAL specificity (national official or public-employment sources give C1 for detailed and C2 for broad occupations; harmonised international sources give C3; regional rows, unknown level, Cedefop and secondary sources give no class and are rejected at import). Authorised secondary evidence never presents as C1 to C3 until the owner defines qualification criteria. The policy is a versioned file (`p10c-c/1`) validated on load: contiguous ordered tiers covering every registry precedence category, no country-specific override or key. Precedence only orders evidence that already matches occupation, geography, reference period, pay basis, statistic and source eligibility.

## 10. Resolution, abstention and conflict handling
`CompensationResolver` (internal): explicit country first (none gives INSUFFICIENT_CONTEXT; `UK` maps to `GB`; nothing is inferred from a language); comparison mode; occupation identity; evidence. Default `require_operational=True` withholds everything not approved for runtime use and qualified (the result is a C4 abstention saying evidence exists but is not operational). Eligible evidence is filtered by region, requested period, statistic and year; recency picks the newest reference year among eligible evidence. Evidence is grouped by comparability (country, region, geography level, currency, pay period, known pay basis, known statistic, reference year): several groups give CONFLICT (not combined; each group's best is listed); inside one group the highest precedence tier wins and lower tiers are reported as corroborating or divergent, never averaged; two same-tier sources that disagree give CONFLICT. No value exists outside an EVIDENCE outcome. A broad (C2) or broader-group or harmonised (C3) result is labelled as such in `coverage_limitations`; the pay basis and data vintage are surfaced.

## 11. Source adapters
US (GKB-7): OEWS annual median wage in USD with published 10th and 90th percentile bounds; level from the source group; the SOC edition is an explicit parameter (default `unknown`, which a production import refuses); pay basis stays `unknown` unless documented; suppression markers become a status; the all-occupations total is skipped. An unverified structural O*NET-SOC prefix link exists (basis derived rule, status partial) and is never used for evidence. EU (GKB-6): a contract for a structured Eurostat table that assumes no Eurostat code (the caller supplies the indicator map and unit-to-currency rules); PPS values are not currency and are rejected; a missing market stays missing; national and EU-aggregate rows are separate geography levels; no EU-wide coverage is claimed. UK: ASHE published gross weekly pay stays weekly in GBP (never annualised or converted), UK SOC 2020 is explicit and versioned (D-03 pending adoption), level from the digit count.

## 12. German evidence limitations
K1 is an engineering draft; no German compensation record exists in V2; `ba_entgeltatlas` is not acquired. Country coverage (German rows) is reported separately from EU-level evidence; Eurostat harmonised data would be C3 and never a substitute for German national evidence.

## 13. Comparison modes
Only nominal comparison is supported. FX-converted and purchasing-power comparisons return NOT_CONFIGURED; `FxProvider` and `PppProvider` are interfaces with no implementation, source or rate. No current exchange rate is ever applied to historical pay. Methodology and sources are PENDING OWNER APPROVAL (D-10).

## 14. Internal response contract and product boundaries
`CompensationResponse.to_public_dict()` carries occupation status and candidates, country, evidence class (C1 to C4), the value as an exact decimal string, original currency, period, basis, statistic, bounds and semantics, reference year, data vintage, a citation built only from the stored measurement and its registered source (publisher, dataset, edition, URL, native code, reference year), coverage limitations, abstention reason, conflicts and corroboration, withheld counts, policy version and the presentable flag. It carries no licence detail, approval metadata, actor, batch, checksum or private provenance. Interfaces are prepared for Career AI, Opportunity workflows, Preparation Packs, Knowledge/RAG, candidate career intelligence and Admin source governance, none is activated, and no second compensation-generation engine exists (Preparation Packs still state compensation is not included).

## 16. Performance (`p10c_c/COMPENSATION_BENCHMARK.json`, synthetic corpora, throwaway SQLite)
Resolution p50 about 2 to 3 ms and at most 9 SQL statements per resolution across small (100 occupations), large (2,000 occupations, 8 countries, 16,000 records) and multi-edition corpora; repeated lookup, conflicting evidence, unavailable market and unresolvable title measured; import of 16,000 rows about 6 s; peak traced memory under 0.4 MiB per batch. The record lookup is index-backed (`ix_comp_v2_lookup`, verified by query plan).

## 17. Security
No import by a runtime or API module and no network or provider import (AST tests); no client path can import, approve or qualify; synthetic sources cannot be ingested as production; untrusted imports cannot grant themselves a status (rows start `unqualified`); the response exposes no registry secret; logs carry no source or candidate content; no live AI dependency.
