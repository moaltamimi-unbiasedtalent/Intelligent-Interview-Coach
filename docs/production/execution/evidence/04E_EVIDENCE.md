## Permission justification (registry stays 44)
An invitation is the right to create a candidate account, which is what `platform.users.manage` governs; listing shows account-access metadata at the sensitivity of the users list (`platform.users.read`). Only the `platform_admin` preset holds `users.manage`, so issuing and revoking is limited to the platform owner. The 403 matrix test asserts every one of the seven personas against both permissions and a test pins the three routes to exactly these permissions. No permission was added and no route is outside `require_permission`.

## Security and privacy impact
- A database read yields no usable credential (hash only); the optional email binding is a domain-separated SHA-256 plus a masked hint, is never returned by any API, and is cleared when the redeemer's account is deleted. A SHA-256 of a guessable address is brute-forceable by someone who already holds the database, which is why the hash is cleared on redemption-then-deletion and the field is optional; a keyed HMAC would need a server secret that the non-encrypted mode does not have.
- Replay, enumeration, wrong-email, expiry and revocation all collapse to one response. A refused attempt with a valid code for another email does not consume it.
- No code, hash or email appears in any log (asserted with `caplog` at DEBUG), audit context, export, list or error.
- Hosted default is fail-closed; the only way to relax the requirement is a local environment label.

## Risks and limitations
- The 1000-pending cap and the rate limits are per process unless a shared limiter is active (existing, unvalidated Redis path).
- Email-bound OIDC invitations require a provider-verified address; an unverified Google address cannot redeem a bound code (intended).
- Registered-but-unverified accounts are unchanged: an invited registrant still verifies the email before sign-in.
- A hosted deployment needs the one-time CLI bootstrap above; nothing else creates the first invitation.
- The invitation link is built from `APP_BASE_URL` (the existing trusted https origin setting); a mis-set value yields a wrong link, not a security hole.
- Admin copy is English-only by decision AD-01; the candidate field and errors are localized.
