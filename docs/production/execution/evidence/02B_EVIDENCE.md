## Risks and limitations
- **Operational consequence:** staging and production now refuse retrieval from an unqualified embedder. `deploy/.env.staging.example` (05A) keeps `COPILOT_EMBEDDING_PROVIDER=auto` with an empty key; a staging deployment started from it will fail closed (governed channel degraded, 503 on the career vector store, guard blocks) until a semantic embedding credential (OD-EMBED) exists. That is the required behaviour; the example file belongs to 05A and was not edited.
- An existing hosted index built before 02B has no manifest and is therefore refused (unproven) until it is rebuilt with `knowledge_embedding_rebuild.py`; there is deliberately no "adopt the existing index as built by embedder X" shortcut because that would invent evidence.
- The rebuild updates the registry's index record (label, count, build time) while it builds into the new directory, before the operator switches; the old index is untouched and still serves nothing wrong, but the registry label can run ahead of the live index until the switch.
- The existing 02A test `test_no_forbidden_files_were_touched_and_no_migration_in_part_one` diffs against the local ref `origin/feat/02k-knowledge-contract` and already fails locally on current `main` (it lists `src/agent/*` files changed by later merges); it also names `src/copilot/embeddings.py`, which this package legitimately owns. In CI that ref does not exist so the diff is empty. The lead should retire or retarget that test; it was left unchanged.
- The curated store is checked by the guard only where the guard is given a curated-store provider (wired in `get_knowledge_guard`); the career vector store itself refuses an incompatible index at query time in all cases.
- Chroma sidecar manifests assume the index directory is the unit of backup (true for 02A backup/restore); a hand-copied `chroma.sqlite3` without the sibling directory loses the manifest and is refused when hosted.
- Dimensions and version are operator-declared for models outside the built-in table; a wrong declaration is not detected until vectors disagree (the OpenAI embedder checks every returned vector against the declared dimensions and refuses mismatches).
