# 02D Evidence: market source qualification and licensing (PR 1: the approval filter)

Branch `feat/02d-source-approval-filter`, from `origin/main` (f5cf7cb). PR 2 (`feat/02d-licensing-review-pack`, documentation for the licensing reviewer) is stacked on this branch because it references the register format defined here.

## What this is, and what it is not
**NO source is approved today and nothing in this PR approves one.** Legal rights verification is a human qualification the owner will appoint. This PR delivers the engineering that makes an approval enforceable and its absence safe: a reviewed, committed register (shipped EMPTY), a fail-closed validator, and a retrieval filter so a Candidate cannot receive an unqualified source. The register is written only by the appointed reviewer; no code, test or script here writes a record into it. Test fixtures use synthetic names and are injected through a test-only seam.

## Security and privacy impact
- Fail closed everywhere: unknown market, unidentifiable source, unreadable register, malformed or partially filled record, stale record and automation-labelled approver all enable nothing. The `enabled` claim is never an input.
- No new data collected or stored; the market is an existing account preference. Counts and source ids only appear in the trace note and `public_summary`; no evidence text, approver name, evidence reference or SHA.
- The test seam refuses outside a running pytest session, and a static test asserts no production module calls it.
- Hosted behaviour changes when approvals are absent: Candidate retrieval over the curated and governed corpus returns no evidence (abstention) in staging and production until a human enables sources. That is the intended safe default and is visible to the owner as "nothing is offered".

## Risks and limits
- Mo's agent path (`SearchCareerKnowledge`) does not carry the account geography yet (`src/agent/*` is owned by the 01D/01C/04C/07B sequence); it uses the country the question names, and with neither it fails closed. Once approvals exist, a Mo user with no named country and no selected geography receives no governed or curated evidence until that plumbing is added. Hand-off: pass `principal.career_geography` into `KnowledgeSearchRequest.market` in `src/agent/tools.py`.
- `trace.sources_considered`, `trace.resolved_occupation` and the occupation resolver still read the role database (for example O*NET titles) before the filter; only evidence delivered to a Candidate is filtered. Those fields are Inspector and reviewer views, not Candidate content, but a reviewer should confirm that reading.
- Admin-governed knowledge also has its own human approval and licence class (W10.8); this register is an additional, market-specific gate on top of it, not a replacement.
- The K1 to K4 governed JSON datasets (`data/knowledge/governed`) have no Candidate-facing caller in `src` today (their lookup functions are reached only from scripts and tests); if one is wired later it must pass through this filter (source id `k1_de_compensation` etc. needs a manifest entry first).
- Evidence-text labelling in development is metadata only, by design.
