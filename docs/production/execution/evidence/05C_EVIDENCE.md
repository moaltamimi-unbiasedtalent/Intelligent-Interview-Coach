## PR 1: production AI budget governor

### Why a migration (0044)
The demonstration ledger is a private SQLite file for one harness. A production governor has to be durable in the APPLICATION database and safe across the API, the worker and evaluation processes at the same time, which cannot be done without a table. `0044_ai_budget_ledger` adds two tables, `ai_budget_controls` (atomic counters, one row per scope) and `ai_budget_entries` (one row per provider call). It is additive (no existing table touched, nothing seeded, no candidate privacy table involved) and its downgrade is fail-closed (it refuses, deleting nothing, while any row exists, because those rows are the only record of what was spent). The file ledger of the demonstration harness (`src/demo_live`) is unchanged and remains separate.

### Operating the governor (owner)
1. Create a JSON file, outside the repository, with `limits`, `pricing.models` (USD per token as OpenRouter publishes them), `classes.<development|evaluation|production>` (`hard_cap_usd`, `stop_usd`, `max_requests`, `categories.<agent|interview|embedding|evaluation>` with the same two fields) and `approval_marker` (`OD-BUDGET:<reference>`). Point `AI_BUDGET_CONFIG_PATH` at it. A class with no `categories` entry for a category refuses that category (fail closed).
2. Apply migration 0044 (`alembic upgrade head`).
3. Hosted API and worker: set `AI_BUDGET_MODE=enforce`, `AI_BUDGET_APPROVED_MARKER=<the same marker>` and (optionally) `AI_BUDGET_CLASS`; unset means the process behaves exactly as before (the governor is opt-in so no existing test or deployment changes). With `enforce` and an invalid or missing configuration, marker or ledger, the process still starts and serves non-AI traffic but every paid call is refused with the reason, and the Admin status shows `closed`/`unavailable`.
4. Scripts: set the same config and marker variables (class defaults to `evaluation`); `python scripts/openrouter_models_probe.py key-status|models`.
5. Kill switch: `AI_BUDGET_KILL=1` in the environment, or set `ai_budget_controls.killed` for scope `global` (an operator action; there is deliberately no web route to change the budget).
Nothing in the repository sets the marker, ships a ceiling value, or reads the owner's `.env`.

### Security and privacy impact
- No prompt, response, key, user identifier or provider text is stored: entries hold class, category, model id, a SHA-256 request fingerprint, money, tokens and latency. A test dumps both tables and the status JSON and searches for the prompt text, the key and `Bearer`.
- Refusals carry fixed reason codes only; neither the marker nor the key is ever echoed (tested).
- Admin status is read-only, allow-listed and on the existing `platform.ai.read`; the 403 matrix (candidate, support operator) is asserted.
- Unknown or unreadable state never looks healthy: unreadable kill switch counts as engaged; counter drift is reported (`ledger_inconsistent`).

### Interview client integration (found while testing)
`OpenRouterClient` retries a timeout once. A timeout is an UNKNOWN outcome, which the governor never re-sends, so with enforcement the retry is refused at the chokepoint. Rather than let a raw `BudgetError` escape into Interview Practice, `_post_chat` now (a) re-raises the truthful earlier failure (timeout, network, 429/5xx) when the governor refuses a retry and (b) raises a new typed `BudgetRefusedError(category="budget_refused")` with a fixed safe message when the first attempt is refused (kill switch, ceiling, closed governor). Behaviour without enforcement is unchanged (all 47 existing client tests pass). The Career/agent path goes through the OpenAI SDK, which wraps a refusal raised inside `httpx` as its connection error (existing handling).

### Risks and limits
- The governor is opt-in per process (`AI_BUDGET_MODE=enforce`); a hosted environment that never sets it is NOT governed. The Admin status reports `enforcement: not_enforcing` in that case. `deploy/docker-compose.staging.yml` (owned by 05A) was not edited; the owner/lead must add the variables there.
- Whole-request budgeting only: streaming is refused by design (usage could not be settled), as in the demonstration guard. A call without an output-token cap is refused (every current call site sets one).
- The in-flight duplicate rule also blocks two users sending byte-identical requests at the same instant; the second gets a safe typed refusal. Accepted trade-off for a cost control.
- Counters are advanced in the database transaction, not summed from entries on every call; `integrity()` recomputes and the status reports drift as `ledger_inconsistent` (never silently repaired).
