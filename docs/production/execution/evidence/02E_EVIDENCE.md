## Risks and limits
1. **Live-client risk for OpenRouter embeddings (not changed, flagged):** `OpenAIEmbedder` wraps `langchain_openai.OpenAIEmbeddings`, which by default pre-tokenises with tiktoken and sends token ids; non-OpenAI models behind OpenRouter generally need raw strings (`check_embedding_ctx_length=False`). The 02B embedder file was not edited here; the first governed run may fail for non-OpenAI slugs until it is. Not verifiable offline.
2. The OpenRouter availability evidence file named in the brief (`OPENROUTER_EMBEDDING_AVAILABILITY_2026-10-22.md`) is not in this tree (not on `origin/main`), so the model slugs and dimensions in `benchmark_models.json` are vendor-published defaults, marked UNVERIFIED; a wrong dimension aborts that model (`dimension_mismatch`), a non-served slug fails its first call and is reported in `failed_models`.
3. A floor proposed from the lexical hash embedder (`eval_relevance_floor.py`) is explicitly not evidence; with that embedder the strictest-no-irrelevant-citation floor costs about 70 percent false abstentions: the trade-off is reported, the choice is the owner's.
4. Routing tables are engineering vocabulary: collisions between Romance-language words are possible (they can only change a retrieval lane, never answer or cite). Question-language guess uses stop words, so very short or mixed queries rely on the fallback order.
5. `route_question` now imports `router_lang` lazily; behaviour for English is asserted equal, but the unchanged-English claim is proven on the committed router cases and fixtures, not on all possible input.
